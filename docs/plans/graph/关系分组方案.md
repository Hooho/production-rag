# 关系分组方案

日期：2026-11-15

状态：方案已整理，尚未实施。

## 目标

减少同一实体组合的多条关系连续占满容量，让其他实体组合获得入选机会。不合并事实、不删除关系、不新增 AI 判断。

## 选择规则

1. 关系重排并过滤低相关内容后，按「起点标准实体 ID＋关系类型＋终点标准实体 ID」分组，保留方向。
2. 每组内部按重排分数排序。第一轮每组取最高分的一条，第二轮取各组第二条，依次继续；每轮内部仍按分数排序，同分沿用原排名。
3. 达到容量上限后停止。按条数模式沿用条数上限；按 token 模式累计实际交付 token，某条装不下就跳过，继续尝试其他关系。
4. 分组选择放在关系重排及相关度过滤之后、最终容量截断和获取出处分片之前，不能先截取前 30 条再分组。

例如容量只能装 5 条时，原来可能取到「GE、GE、腾讯、GE、腾讯」；分轮后先取「GE、腾讯、苹果、新东方」，再补 GE 的第二条。

使用现有实体归属。已合并的别名进入同组；GE 与通用电气尚未合并的情况保持分开，本次不处理实体消歧。所有原始关系、描述和出处继续保留，只调整选择顺序，不限制每组最多返回几条。

## 与容量方案配合

本方案调整关系选择顺序，候选容量和最终 token 分配遵循同目录的《检索容量控制改造方案》。关系优先交付，原文统一重排竞争剩余容量，父子扩展使用余额。

## 前端展示

评测和回答的检索步骤中，在「关系重排」之后、「取分片」之前新增「关系分组」。两处复用展示逻辑。

步骤显示分组数和入选关系条数，按 token 模式同时显示实际占用容量。点开可查看各组关系、重排分数、选择轮次和入选结果，沿用现有详情及原文查看组件。

后端保存对应分组与选择结果，前端按实际结果展示。历史记录没有分组数据时，不显示新步骤。

## 验证

重跑当前批次 `20261115-084753-0c16a1` 对应的 9 题，确认公司汇总题覆盖更多实体，同时网易事件题仍能选入同组的多个有效事实。检查容量不超限，已归并别名正确分组，前端展示与实际交付一致。

允许不同组较低分关系先于同组第二条高分关系入选，这是提高覆盖面的取舍；所有入选关系仍须通过相关度门槛。
