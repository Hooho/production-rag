# 取消图原文保底方案

日期：2026-11-16

状态：方案已整理，尚未实施。

## 目标

图独有原文已经有独立进入重排的机会，最终交付时不再按召回来源保底，由统一重排结果决定哪些原文进入上下文。

图关系继续交付，关系与原文共同占用最终资料 token 预算，不再通过固定比例分配。

## 交付规则

1. **关系先放。** 保留现有关系重排、相关度过滤、分组开关及关系条数上限（当前默认30条）。入选关系按实际选择顺序优先装入最终总预算；某条装不下就跳过，继续尝试后续关系。不新增独立关系 token 上限，仍受总预算约束。
2. **原文公平竞争。** 关键词、向量和图检索找到的原文合并去重、统一重排。过滤低相关内容后，按重排分数使用剩余预算，不再给图独有分片保底。某段装不下时继续尝试后续分片。
3. **扩展最后放。** 先完成直接命中子块的选择，有余额再做父子扩展。扩展去重后只计算新增 token，不挤掉已入选的直接证据；父块装不下时仍保留命中子块。直接证据装满时允许不扩展。

例如最终总预算为12,000 token，关系使用2,600，原文就竞争剩余9,400；直接原文装完还有余额，才用于扩展。

相关度门槛继续生效，不为了填满容量保留无关资料。关系交付沿用现有可靠性检查；取消比例不能绕过重排失败等检查，也不能因为比例配置被移除而停止正常关系交付。

## 配置和展示

- 系统设置、评测参数及新建评测配置中移除“图检索保底比例”，不将其作为新流程的容量分配依据。
- 新报告和回答检索步骤显示最终预算，以及图关系、直接原文、父子扩展各自实际占用的 token；不再显示图保底额度或图保底入选。
- 历史报告按当次保存的配置和诊断展示，保留原比例和保底结果，不追溯改写。
- 旧评测模板、重跑参数中携带的比例需要兼容处理：进入新流程时忽略旧比例，不因过期参数导致执行失败；新运行的实际配置应明确采用新交付规则。

## 不变的部分

普通原文候选池、图独有原文候选池、关系候选数量、相关度门槛、关系分组规则及条数上限保持现状。图独有分片仍单独获得进入统一重排的机会。

按条数选择来源的模式保持现有行为。本方案只调整按 token 模式下的最终资料分配及扩展顺序。

本方案不实施《检索容量控制改造方案》中“前面各阶段改用 token 候选预算”的设计；两项工作不捆绑。之前方案文档保留，本次不修改。

## 验证

- 使用相同召回候选、重排分数、关系选择结果和最终预算，对比原保底规则与新规则，避免重新召回造成干扰。
- 检查原文按统一重排分数选择，不再按图来源优待；图关系仍能正常交付，且按关系选择顺序装入。
- 检查直接证据先于扩展占用容量、重叠内容不重复计量、装不下的条目不阻塞后续内容，最终总量不超预算。
- 对比计分项命中、完整通过率，以及关系、直接原文和扩展的实际 token 用量。
- 检查历史报告、旧模板、重跑参数兼容，以及重排失败等回退路径。

实施时补充必要测试，每完成一个功能单独提交，并根据实际改动提供 `docker-compose` 更新命令。
