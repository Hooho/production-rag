# 北海旅游 Agent 评测材料

只使用一份语料：[北海慢游指南.md](corpus/北海慢游指南.md)。全文 35,112 字符、136 个小节，包含三类题需要的全部资料；400/40 或默认 800/120 切分均为 137 片。原 120 个小节保持内容和顺序，四道新版比较题的 16 个短小节已并入同一文档。

## 文件

- [北海慢游指南](corpus/北海慢游指南.md)：唯一需要进入评测语料库的文件。
- [questions.json](questions.json)：一键导入的十二道题，每类四道，含答案、计分项与小节标识；不作为语料上传。
- [评测题与评分依据](评测题与评分依据.md)：十二道正式题与六道备用题的评分说明，不上传语料库。
- [结构检查记录](结构检查记录.md)：静态切分、唯一线索和多跳距离，不上传语料库。
- [比较重排验证.json](比较重排验证.json)：合并后文档的本地模型实测，不上传语料库。

## 一键更新

此次增加了单份语料更新接口 PUT /eval/corpus/{id}，部署时只需更新 API 服务：

> docker-compose up -d --build --no-deps api

API 就绪后，在仓库根目录运行原命令：

> python3 scripts/import_beihai_questions.py

自动读取 .env 或进程环境里的 API_PORT（默认 8000）、ADMIN_PASSWORD，用 admin 登录；进程环境优先。配置缺少密码时才提示输入，密码不显示。也可用 BEIHAI_API_TOKEN。其他账号或地址可以通过 --username、--base-url 指定。

脚本只处理《北海慢游指南》：未上传时上传，已是已知旧版本时原位更新，之后自动重新导入。语料编号与标题不变，不创建补记文档；未知版本不会覆盖。新原文写好后切换数据库指向，旧原文保留用于恢复；重新导入成功前仍使用旧检索版本。此次未执行真实环境部署或导入。

题目仍在“北海旅游三类检索”专项中：用 PUT 更新原四道比较题并保留原题 ID，多跳与汇总八题不改。已用过独立补记版的相同四题，会把其相同证据重新绑定到指南。重复运行跳过一致内容，中途失败可再次运行续导；人工改过答案或证据的冲突会中止。多个请求不是同一事务，请勿同时启动多个导入进程。

如需只预检查，在原命令后加 --dry-run：不更新原文、不导入、不修改题目；密码登录会创建正常登录会话。缺少新版本语料时会说明正式运行将更新什么。

评测时只勾选《北海慢游指南》，不要上传答案和验证报告。如果之前已经上传过独立补记，本套题不再引用它，脚本不会自动删除它；无需选中该补记参与本套评测。

## 三类设计与验证边界

多跳仍是六条四资料链，四条纳入一键导入。原始线索未修改，相邻两跳至少相差 18 个分片位置。直接检索能否绕过中间节点还需按实际配置检查。

新版比较题把作品养护、电子交付、退款、桌位与押金规则分散到不同小节，每题四项。本地缓存 BGE 模型、仓库默认 0.85 阈值下，每题都有必要片对完整问题低于阈值、对相应子问题高于阈值；具体召回名次和候选池见验证报告。合并文档后已重新运行，未沿用独立补记版分数。

这是本机 PyTorch 权重实测，不是部署中的 fastembed/ONNX 或线上 Milvus 测试；未测 BM25、上下文增强、父块恢复及 Agent。诊断子查询不提供给 Agent，不能据此宣称 Agent 已经会拆解。线上实际配置不同需要复核。

汇总仍从安静、舒服、少操心等宽泛目标出发，关注发现限制后是否调整查询角度。固定计分项只是一套证据覆盖清单，其他合理路径仍需人工核对，不以查询次数多作为成功。

本机已有 torch、transformers 与两个 BGE 模型缓存时运行：

> .venv311/bin/python scripts/verify_beihai_comparisons.py

只读取本机缓存，不下载模型、不连接远程服务、不改评测库；不满足筛选条件时返回非零状态。报告包含源文档与题目指纹、模型修订、参数、原四题基线和新版分数。
