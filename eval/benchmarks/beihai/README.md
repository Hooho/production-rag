# 北海旅游 Agent 评测材料

这是一套以北海慢游为外壳的虚构资料，重点是检索与推理过程，不是提供真实旅游决策。原指南共 33,297 字符、120 个小节，另有 1,910 字符、16 个小节的比较补记；评测文档共 18 题，一键导入其中 12 题，每类四道。

## 文件

- [北海慢游指南](corpus/北海慢游指南.md)：先在语料库上传并完成导入。
- [北海出游条件补记](corpus/北海出游条件补记.md)：新版四道比较题的分散证据，一键脚本自动上传并导入。
- [评测题与评分依据](评测题与评分依据.md)：问题、证据路径、标准答案、评分与运行诊断；不导入知识库。
- [结构检查记录](结构检查记录.md)：本地切分结果、连接标识唯一性和证据间距；不导入知识库。
- [questions.json](questions.json)：选用的十二道题，每类四道，含参考答案、计分项及对应小节；只供导入脚本读取，不上传语料库。
- [比较重排验证.json](比较重排验证.json)：本机缓存 BGE 模型的召回名次、候选池与重排分数；不上传语料库。

## 使用

1. 在评测语料库上传指南，点击“导入”，或在发起评测时由系统导入。
2. 导入后查看分片。推荐 400 字符、重叠 40 字符；实际切分器在此配置生成 121 片，平均正文约 254 字符。默认 800/120 在本材料上同样是 121 片，因为标题隔开了短小节。
3. 如果修改分片参数，重新导入指南，不能只修改文档说明；全局参数也会影响其他后续导入。本次没有修改任何运行参数。
4. 可在界面手动录入，也可使用下方脚本把十二道题通过 API 写入专项。Markdown 答案文件不能直接作为题目上传。
5. 运行时选择指南与补记两份语料，确保答案文件不参与检索。正文的 B 编号用于评测人员核对证据，不把编号或参考查询泄漏给 Agent。
6. 先排查多跳直接检索捷径，再诊断比较题的过滤前后候选，最后观察汇总题的查询调整。不能仅凭最终答案判定目标机制是否被测到。

## 三类设计

多跳采用六条四资料链。问题只给起点，后续的机构、批次、规格和接收端依次出现；终点不给起点活动名。400/40 下相邻两跳最小位置差为 18，即中间至少隔 17 片。全文不存在把整个关系直接说完的答案表。

原四道住宿比较题已被本地基线证实过于容易，完整问题重排分约 0.94—1.00。新版改用手作养护、电子交付、退款、座位与押金等主题分散的记录，每题四项。按仓库默认 BGE 模型、0.85 阈值实测，16 份证据在各自子查询下均为向量第 1 名且进入融合前 12 候选；每题都有必要片对完整问题低于阈值、对子问题高于阈值。原始分数见验证报告。

这是本机 PyTorch 缓存权重实测，并非部署中的 fastembed/ONNX 或线上 Milvus 测试；未测 BM25、上下文增强、父块恢复及 Agent，线上实际阈值也未读取。诊断子查询不是给 Agent 的提示，不能据此宣称 Agent 已经会拆解。

汇总从安静、舒服、少操心、不扫兴、不将就等宽泛需求出发。线索可能暴露声源、楼梯、饭点、天气或取物限制，促使 Agent 转查新的维度，甚至放弃最初候选。没有唯一查询路径或唯一旅行路线；按证据支持的调整与约束满足评分，不奖励无意义的长过程。

## 更新与服务

材料与导入脚本不修改应用服务代码、配置或现有种子评测集，不需要重建或重启服务。仓库 compose.yaml 已挂载 eval，但放进本目录不会自动登记到语料库。指南需先上传；运行脚本后会自动登记补记并创建或更新题目。

若现有依赖服务已运行、仅需确保 API 已启动，可以执行：

> docker-compose up -d --no-deps api

这条命令只确保 API 服务运行，不会自动导入本套材料。没有在本次工作中执行部署、连接远程服务器或修改运行环境。

## 通过 API 导入十二道题

先上传与本仓库同版本的指南，并等待状态变为“已导入”。在仓库根目录执行一条命令即可，无需额外依赖：

> python3 scripts/import_beihai_questions.py

自动使用本机 API，从项目根目录 .env 或进程环境读取 API_PORT（默认 8000）和 ADMIN_PASSWORD，用 admin 登录；进程环境优先。只解析这两个配置值，不执行 .env，不打印密码。配置缺少密码时才提示输入。若管理员密码已在页面修改，需以当前密码为准，不能继续依赖首次初始化密码。

如需先检查不写入，在命令后加 --dry-run。非本机地址可用 --base-url，其他管理员账号可用 --username；这两种情况不会自动使用本机配置密码，而是提示输入。

输入密码不会显示。脚本不会从浏览器提取登录信息。已有访问令牌时可通过环境变量 BEIHAI_API_TOKEN 提供，脚本就不再登录。

默认创建或复用“北海旅游三类检索”专项，评测方式为检索，检索方式为混合检索。可用 --suite-name 指定其他名称。预检查会鉴权和读取数据，不上传、不导入、不创建或更新题目；缺补记时会说明正式运行将执行的操作。使用密码时登录本身会创建正常登录会话。

脚本先核对指南版本和导入状态，再上传缺少的补记并等待其导入，最后匹配全部计分项后写入题目。相同标题但不同版本的补记会中止，不覆盖或删除。目标分片按实际正文及指纹匹配，不使用固定分片序号；小节拆成多片时逐片建成必需计分项，避免误设为命中任一片即得分。若单题超过 API 的十项上限，会在写入题目前停止，建议按 400/40 重新导入。

相同题目、类型、答案与分片标注会跳过。新版四题通过 previous_question 精确定位旧比较题并用 PUT 更新，保持原题 ID；多跳、汇总与用户其他题目不更新。新旧比较题同时存在、同题内容有差异或同名专项方式不同会中止，不批量删除。多个请求不构成数据库事务，中途失败后成功内容保留，重复运行可以续导；不要同时启动多个进程。脚本不自动运行评测。导入后查看十二道题，评测时勾选指南与补记。

汇总题的计分项是一套固定证据覆盖清单，不能覆盖所有合理探索路径；其他路径是否有道理仍需人工查看运行记录。本次脚本只录入已确认的十二道题，不导入其余六道备用题。

## 复核本地模型结果

本机已有 torch、transformers 和两种 BGE 缓存权重时可运行：

> .venv311/bin/python scripts/verify_beihai_comparisons.py

脚本禁止下载模型，只读取本机 Hugging Face 缓存，按仓库默认参数重新生成验证报告。它不读取线上配置、不连接远程服务器，也不修改评测库。分数变化或任一题不再满足条件会返回非零状态。
